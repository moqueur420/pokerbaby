# Матч: этап 5

Реализованы М-1—М-3, сценарий Т-14 и относящиеся к матчу ограничения П-2—П-4, П-8 и П-9. `MatchState` — неизменяемый record в пакете `io.pokerbaby.engine`, представляющий положение между раздачами.

## Создание и данные

```java
MatchState match = MatchState.start("m1", List.of("human", "bot"),
        GameConfig.DEFAULT, SeatChips.of(10_000, 10_000), 0);
```

| Значение | Смысл |
| --- | --- |
| `matchId()` | Переданный извне непустой идентификатор матча |
| `playerIds()` | Два различных непустых идентификатора в постоянном порядке мест 0 и 1 |
| `config()` | Блайнды матча |
| `stacks()` | Текущие стеки перед следующей раздачей либо после завершения матча |
| `buttonSeat()` | Баттон следующей раздачи; меняется после каждого применённого результата |
| `handNumber()` | Положительный `long`, номер следующей раздачи начиная с 1 |
| `completedHands()` | Количество применённых результатов: `handNumber - 1` |
| `isOver()` | Признак нулевого стека одного из игроков |
| `winnerSeat()` | Победитель завершённого матча, иначе пустой `OptionalInt` |

Начальные стеки — от 1 до 10¹² у каждого игрока, общая сумма не выше 2·10¹². В последующих состояниях стек может превышать 10¹² после выигрыша либо стать нулевым. Общая сумма остаётся исходной. Положение с двумя нулевыми стеками не допускается.

Конструктор record проверяет те же ограничения начального состояния при `handNumber == 1`. Для последующих номеров применяются ограничения текущих стеков. Это позволяет хранить результат выигрыша без повторного применения начального лимита.

Список игроков копируется и возвращается неизменяемым; значения фишек хранятся в `SeatChips`. Смена баттона сохраняет места и идентификаторы игроков. Состояния сравниваются по значению, общего изменяемого состояния нет.

## Начало очередной раздачи

```java
HandMeta meta = match.nextHandMeta();
// handId == "m1-h1"; playerIds == [human, bot]; startedAt == Optional.empty()
HandState hand = match.nextHand(Deck.shuffled(42));
```

Идентификатор выводится детерминированно: `matchId + "-h" + handNumber`. Время не генерируется. Повторные вызовы `nextHandMeta()` возвращают равные метаданные.

`nextHand(deck)` передаёт конфигурацию, метаданные, текущие стеки, баттон и явно указанную колоду в `HandEngine.start`. Колоду подготавливает вызывающий код. Применяются проверки движка, включая минимум девять оставшихся карт. После коротких блайндов возвращаемая раздача может оказаться уже завершённой.

Обе операции сохраняют прежний матч. Номер увеличивается только после применения результата. Вызывающий код также может самостоятельно вызвать `HandEngine.start` с метаданными от `nextHandMeta()` и добавить время начала извне.

## Применение результата

```java
HandResult result = completedHand.result().orElseThrow();
MatchState next = match.afterHand(result);
```

`afterHand` принимает только результат ожидаемой раздачи. Перед переходом сравниваются:

- Точный идентификатор `matchId-hN`.
- Идентификаторы обоих игроков в исходном порядке мест.
- Конфигурация блайндов.
- Баттон раздачи.
- Начальные стеки раздачи и текущие стеки матча, по каждому месту.

Время начала не участвует в принадлежности результата: допускается явно переданный вызывающим кодом timestamp. Согласованность вкладов, возвратов, выплат и конечных стеков проверяется самим типом `HandResult`.

При успешном переходе стеки берутся из `result.finalStacks()`, баттон становится `1 - buttonSeat`, номер увеличивается на один. Идентификатор матча, порядок игроков и блайнды сохраняются. Это выполняется и после ничьей, и после последней раздачи матча.

Чужой, устаревший или несогласованный результат даёт `IllegalArgumentException`. `null` даёт `NullPointerException`. Счётчик увеличивается через `Math.incrementExact`; при переполнении возникает `ArithmeticException`. Отклонение не изменяет исходное состояние.

После перехода следует использовать возвращённый `MatchState`: повторное применение прежнего результата к нему будет отклонено. Прежний неизменяемый объект сохраняется и позволяет повторить тот же розыгрыш или построить другую ветвь. Истории доступны через `HandState.history()`; вызывающий код может сохранять их после каждой раздачи.

## Завершение

Если после выплаты стек одного игрока равен нулю, `isOver()` возвращает `true`, а `winnerSeat()` указывает игрока со всеми фишками. В завершённом матче `nextHandMeta()`, `nextHand(deck)` и `afterHand(result)` дают `IllegalStateException`. Докупка и изменение блайндов в этот API не входят.

Даже в завершённом состоянии счётчик хранит номер, который следовал бы за последней раздачей; число сыгранных доступно через `completedHands()`. Например, после первой раздачи с выбыванием `handNumber == 2`, `completedHands == 1`, `isOver == true`.

## Демонстрационная программа

```powershell
# По умолчанию seed 42, показ до двух раздач
.\gradlew.bat :poker-engine-demo:run

# До десяти раздач одного матча
.\gradlew.bat :poker-engine-demo:run --args="42 10"

# Больший лимит для показа завершения
.\gradlew.bat :poker-engine-demo:run --args="42 1000"
```

Демо использует `MatchState` и фиксированную учебную политику ставок предыдущего этапа. Один `Random(seed)` подготавливает очередную колоду для каждой раздачи; сам матч случайностью не управляет. Формат аргументов — `[seed] [maxHands]`, по умолчанию `42 2`; лимит обязан быть положительным целым числом.

При seed 42:

| Раздача | Баттон | Начальные стеки | Итоговые стеки |
| --- | --- | --- | --- |
| `demo-h1` | human | `[10000, 10000]` | `[8950, 11050]` |
| `demo-h2` | bot | `[8950, 11050]` | `[10000, 10000]` |

После двух раздач демо сообщает о лимите показа и следующей раздаче `demo-h3` с баттоном `human`. При лимите 1 000 тот же матч заканчивается на 77-й раздаче: `human` получает все 20 000 фишек. Если матч завершился раньше лимита, новая раздача не создаётся.

Случайная политика ботов и JSON-вывод относятся к этапу 7. Следующий этап 6 — воспроизведение и возобновление раздачи.
