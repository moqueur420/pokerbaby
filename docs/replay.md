# Воспроизведение и возобновление раздачи

Этап 6, 13 ноября 2026 года. Требования И-1—И-7, Ф-2, Ф-5—Ф-7 и §8.4 ТЗ.

## Публичный API

| Тип | Назначение |
| --- | --- |
| `HandSnapshot` | Наблюдаемое состояние после события, без колоды; неизвестная рука представлена пустым списком |
| `ReplayStep` | Номер события, само событие и снимок после него; шаг 0 содержит начальный снимок без события |
| `Decision` | Снимок непосредственно перед действием и `HandEvent.ActionTaken` |
| `ReplayResult` | Шаги, точки решений и признак независимой проверки результата |
| `ReplayException` | Некорректная история с номером события |
| `HandReplayer` | Чистое воспроизведение истории без случайности и подставных карт |

```java
ReplayResult replay = HandReplayer.replay(history);
List<ReplayStep> steps = replay.steps();
List<Decision> decisions = replay.decisions();
HandSnapshot last = replay.lastSnapshot();
```

Для N событий возвращается N+1 шагов. Первый снимок показывает стартовые стеки, пустой борд и неизвестные руки до постановки блайндов. Шаги хранят независимые неизменяемые префиксы истории. Сданные позже карты не добавляются в ранние снимки.

Поддерживаются завершённая история, пустая история и префикс, заканчивающийся в точке решения. Префикс, оборванный посреди обязательных автоматических переходов, отклоняется с номером следующего требуемого события. Промежуточные снимки таких переходов доступны в шагах полной истории.

## Проверка событий

Воспроизведение последовательно проверяет:

- Очередь и суммы обоих блайндов, порядок известных закрытых рук.
- Очерёдность игрока, доступность действия, минимальные и максимальные размеры.
- Закрытие круга торговли, право хода большого блайнда после лимпа, короткие олл-ины.
- Обязательность возврата неуравненной ставки и точность его суммы.
- Порядок улиц, число общих карт и уникальность всех известных карт.
- Порядок вскрытия, совпадение карт с приватной сдачей и заявленную категорию.
- Победителя, полную выплату банка или равное деление при неизвестном исходе.
- Сохранение фишек после каждого события, включая отдельные выплаты при ничьей.

`BettingRules` — общий внутренний расчёт допустимых действий, границ, закрытия улиц и досдачи для `HandEngine` и `HandReplayer`.

`ReplayException.eventNumber()` использует нумерацию с 1. Для отсутствующего события после конца списка возвращается N+1. Входные объекты и уже построенные снимки не изменяются.

## Неизвестные карты и результат

Приватный `DealHole` разрешено пропускать. На вскрытии неизвестный игрок может раскрыть руку событием `Showdown`; тогда карты становятся известны только с этого шага. Если карты уже присутствовали в `DealHole`, соответствующий `Showdown` обязателен.

Если неизвестны и приватная сдача, и вскрытие одного игрока, его карты и комбинация остаются неизвестными. Торговля, возвраты и выплаты всё равно проверяются. Допустимы только весь банк одному игроку или две равные выплаты.

`outcomeVerified()` равен `true` после фолда либо завершённого вскрытия с обеими известными руками. Для неполной истории и результата с неизвестной рукой он равен `false`. Признак завершения можно прочитать через `lastSnapshot().isComplete()`.

Снимок полной истории может содержать приватные карты обоих игроков. Для передачи клиенту используйте `snapshot.forPlayer(seat)`: он удаляет приватную сдачу соперника, его карты и комбинацию до соответствующего события вскрытия. Колоды нет ни в полном, ни в скрытом снимке.

В промежуточных снимках выплаты уже оплаченная сумма вычитается из оставшегося банка: сначала из вклада места 0, затем места 1. Это фиксированный порядок учёта остатка банка; он не меняет фактические вклады и выплаты в `HandResult`. После полной выплаты банк, текущие ставки и вклады равны нулю.

## Продолжение игры

```java
HandState first = HandEngine.start(GameConfig.DEFAULT,
        new HandMeta("resume-example", List.of("human", "bot")),
        SeatChips.of(10_000, 10_000), 0, Deck.shuffled(42));
HandState ended = HandEngine.apply(first, 0, Action.fold());
ReplayResult replay = HandReplayer.replay(ended.history());
HandSnapshot snapshot = replay.decisions().getFirst().snapshot();
HandState resumed = HandEngine.resume(snapshot, first.deck());
// resumed.equals(first)
HandState alternative = HandEngine.apply(resumed, 0, Action.raiseTo(250));
```

`resume` принимает только точку решения с известными двумя руками. Она повторно проверяет префикс истории, сравнивает снимок с восстановленным состоянием и создаёт `HandState`. Поэтому подмена последней прибавки, очереди или множества уже ходивших игроков отклоняется.

Остаток колоды передаёт вызывающий код. Он должен содержать не меньше недосданных общих карт и не пересекаться с уже известными картами. Порядок будущих карт в истории не хранится. С исходным остатком и теми же действиями продолжение даёт исходный итог; допустима и другая подходящая колода для альтернативного продолжения.

Начальный снимок, автоматические переходы, завершённая раздача и скрытый снимок с неизвестным соперником не подходят для возобновления. `apply` по-прежнему принимает только `HandState`.

## Браузерный интерфейс

Сервер хранит до 20 недавних раздач вместе с исходными колодами и состояниями матча до их начала. Данные живут в текущей cookie-сессии до перезапуска сервера или нового матча.

В блоке «За столом» можно выбрать раздачу и открыть просмотр. Стрелки и ползунок меняют только отображение. Карты и журнал показывают сведения, известные на выбранном шаге. Обычные игровые действия в режиме просмотра отключены.

«Продолжить отсюда» доступно в точке решения игрока. После подтверждения сервер:

1. Проверяет версию сессии, доступность раздачи и номер шага.
2. Возобновляет полный серверный снимок с исходным остатком колоды.
3. Возвращает матч к состоянию перед выбранной раздачей.
4. Удаляет старое продолжение и более поздние раздачи.

При новой выплате результат применяется к матчу один раз. Бот выбирает новые действия своей текущей стратегией; сохранение порядка карт не фиксирует будущие решения бота.

Веб-операции: `GET /api/replay?hand=N` для просмотра и `POST /api/resume` с полями `version`, `hand`, `step` для продолжения. Служебный ответ веб-приложения содержит только проекцию для игрока; сохранение и загрузка истории в формате JSON ТЗ остаются этапом 7.

## Проверка завершённости этапа 6

| Требование | Результат проверки |
| --- | --- |
| И-1, И-2 | История событий сохраняется; снимок отделён от `HandState`, колоды в нём нет |
| И-3 | Возвращаются N+1 шагов и отдельные пары «снимок перед решением — действие» |
| И-4 | Проверены порядок, очередь, суммы, карты, возвраты, выплаты и номер ошибки |
| И-5, Ф-2 | Проверены все девять допустимых сочетаний наличия приватной сдачи и вскрытия двух рук; неизвестные карты не подставляются |
| И-6 | Исходное продолжение совпадает; другая допустимая колода принимается; известные карты в остатке, недостаток карт, подмена контекста и промежуточные снимки отклоняются |
| И-7 | Сравнение живых состояний со снимками на 240 случайных раздачах, а также при разных блайндах и сумме стеков 2·10¹² |
| Ф-5, Ф-6 | Проверены обязательные положительные возвраты и выплаты, частичная выплата при ничьей и несовпадающие карты вскрытия |
| Ф-7 | В истории нет полей для несданных карт или seed; остаток колоды передаётся только в `resume` |
| Браузер | Просмотр последних раздач, скрытие будущих карт, продолжение с решения игрока, отмена, восстановление связи и узкий экран проверены в Chrome |

Незавершённых пунктов этапа 6 не обнаружено. JSON-формат сохранения истории и массовые проверки с миллионом раздач относятся к этапам 7 и 8.
