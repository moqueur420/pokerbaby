## Условия измерения

- Windows 11, amd64; Intel Core i7-12700H.
- Eclipse Temurin Java `21.0.13+9-LTS`, OpenJDK 64-Bit Server VM.
- Один рабочий поток; `-Xms512m -Xmx512m -XX:ActiveProcessorCount=1 -XX:+UseSerialGC`.
  Привязка к физическому ядру не задавалась.
- Бенчмарки запускаются последовательно, отдельно от JUnit и JaCoCo.
- Перед каждым случаем — не менее 2 секунд прогрева и не менее двух полных
  пакетов операций. Затем три измерения, каждое не короче 1 секунды и с целым
  числом пакетов. Итог — медиана скоростей трёх измерений.
- Контрольные суммы вычисляются в измеряемом коде и потребляются после каждого
  пакета; результаты `HandRank`, `HandState`, `SeatChips` и `Deck` сохраняются в
  volatile-поля, чтобы JVM не заменила измерение вычислением одного числа.
- Микробенчмарки находятся только в source set `benchmark` и не входят в JAR
  ядра. Внешние зависимости в ядро и бенчмарки на этапе 0 не добавлялись.

```powershell
.\gradlew.bat :poker-engine-core:benchmarkEvaluator :poker-engine-core:benchmarkHands
```

Публичного `HandEvaluator.strength(mask)` в исходном API ещё нет: скорость
внутреннего `HandValues.score` служит ориентиром, но не подтверждает приёмку
будущего публичного метода с проверками входной маски.

В этом запуске разброс `(max - min) / median` составляет 10,5 % для публичного
оценщика и 1,7–7,7 % для остальных случаев. Измерения оценщика остаются
ориентировочной базой; перед выводом о выполнении задачи 1 нужен замер через
JMH согласно разделу рисков ТЗ. Зависимости JMH допускаются только в бенчмарках.
Разницу на уровне этого разброса нельзя считать доказанным ускорением.

## Сценарии и воспроизводимость

### Оценщик

До запуска таймера подготавливается 4 096 семикарточных рук из колод с
`Random(20261113)`. Публичный случай возвращает полноценный `HandRank`, включая
категорию и канонические лучшие пять карт. Он потребляет карту результата и ключ
сравнения. Для `mask + score` маска строится при каждой операции; для `score(mask)`
маски всего корпуса подготовлены заранее. Эти два внутренних случая имеют
доступ к пакетным методам только за счёт пакета benchmark-класса.

Размер пакета публичного случая — 1 000 000 оценок; внутренних — 20 000 000.
Контрольные суммы пакета: `2292160469499` для публичного случая и
`45841992306740` для обоих внутренних.

### Полные раздачи

Стеки по 10 000, блайнды 50/100, баттон чередуется. Один пакет — 100 000 раздач.
Каждая раздача записывает полную историю, завершается выплатой и публикует
полное конечное состояние. Реплей и возобновление в замер раздачи не входят.

Фиксированный сценарий сохранён: рейз до 250 / колл, бет 300 / колл, чек / чек,
бет 500 / колл; восемь решений и восемь представлений `PlayerView`. Корпус
4 096 колод подготовлен через `Random(20261113)` до таймера.
Контрольная сумма пакета: `1783071822`.

Случайная политика равновероятно выбирает доступный тип действия в явном
порядке FOLD, CHECK, CALL, BET, RAISE; для ставки равновероятно выбираются минимум,
максимум или случайная допустимая сумма. Генератор действий — `Random(20261114)`,
заново создаётся для каждого пакета. После 64 решений политика играет пассивно;
128 решений — защитный предел. Генерация действий входит во время измерения.
Это тестовая политика бенчмарка, а не реализация ботов исходного этапа 7.

Три случайных случая измеряются отдельно:

1. Только движок: предсозданные колоды, действия через `HandEngine.legalActions`.
   Контрольная сумма пакета — `996309204`.
2. Движок и `PlayerView`: те же колоды и решения, представление строится в каждом
   ходе, его история и карты потребляются. Контрольная сумма — `2091609618`.
3. Полный цикл: дополнительно новая тасовка внутри каждого измеряемого запуска
   раздачи через отдельный `Random(20261113)`. Контрольная сумма — `2096297351`.
   Этот более полный сценарий используется для контроля цели 250 тыс. раздач/с.

### Фишки и колода

`SeatChips.with` использует 4 096 заранее созданных исходных объектов, меняет
место и сумму, потребляет `total()` и сохраняет полученный объект. Пакет —
10 000 000 операций; контрольная сумма — `497637694464`.

`Deck.shuffled(seed)` вызывается с seed `20261114 + index`, включая создание
генератора, стандартной колоды, проверку и тасовку. Пакет — 200 000 колод;
контрольная сумма — `12000229`.

## Корректность перед оптимизациями

Полная сборка `build` прошла: 271 тест, 0 ошибок, из них 256 тестов ядра.
Покрытие строк ядра: 1 041 из 1 042, **99,90 %**. Порог сборки остаётся 90 %.
Golden-корпус содержит 10 000 исходных раздач и защищён фиксированным SHA-256.
Большой стресс-тест проверил 50 000 раздач и 90 194 продолжения из каждой точки
решения; быстрый — 1 000 раздач и 1 726 продолжений. Все проверки прошли.

Значения из PDF и прежние предварительные замеры в `hand-evaluator.md` и
`hand-engine.md` получены с другой методикой и прогревом. Для таблиц «до/после»
следующих задач используется эта зафиксированная базовая линия.
