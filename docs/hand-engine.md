# Полная раздача: этап 4

Реализованы требования С-1—С-8, Д-1—Д-5, Р-1—Р-3 и относящиеся к ним проверки входных данных. Ядро проводит одну раздачу безлимитного холдема между местами 0 и 1. Внешних зависимостей времени выполнения нет.

## Операции и состояние

```java
HandState state = HandEngine.start(config, meta, startingStacks, buttonSeat, deck);
LegalActions legal = HandEngine.legalActions(state);
HandState next = HandEngine.apply(state, seat, action);
PlayerView view = state.viewFor(seat);
```

`HandEngine` не хранит состояния, не генерирует идентификаторы и не обращается к часам или источникам случайности. Метаданные и уже подготовленная колода приходят от вызывающего кода. Вся изменяемая работа внутри одного вызова остаётся локальной; опубликованные состояния и вложенные коллекции неизменяемы.

`start` требует два положительных стека с суммой не больше 2·10¹² и не менее девяти оставшихся карт. Используется текущая позиция колоды: карты до неё больше не сдаются. Баттон ставит малый блайнд, соперник — большой, каждый не больше собственного стека. Карты сдаются по одной, начиная с игрока без баттона, два круга подряд. Сжигания нет.

`HandState` содержит:

| Поле или метод | Смысл |
| --- | --- |
| `street()` | PREFLOP, FLOP, TURN, RIVER либо COMPLETE |
| `board()` | Общие карты в порядке сдачи |
| `holeCards()` | Две пары закрытых карт по местам; внутри пары — порядок получения |
| `stacks()` | Ещё не поставленные фишки |
| `streetBets()` | Вклады только на текущей улице |
| `contributions()` | Полные текущие вклады за раздачу |
| `pot()` | Сумма вкладов, без повторного прибавления ставок улицы |
| `actingSeat()` | `OptionalInt` с местом следующего игрока; пустой после выплаты |
| `lastRaiseIncrement()` | Последняя полная прибавка; в начале улицы — большой блайнд |
| `actedSeats()` | Кто уже действовал на улице; блайнды ходом не считаются |
| `deck()` | Неизменяемая колода с курсором |
| `history()` | Полная история, включая закрытые карты обоих игроков |
| `result()` | `Optional<HandResult>`, присутствует после выплаты |

`config()`, `meta()` и `buttonSeat()` читаются из заголовка истории. `isComplete()` определяется наличием результата. Одинаковые входы и действия дают равные состояния и одинаковые хеш-коды.

Конструктор состояния проверяет размеры и уникальность карт, отсутствие известных карт в остатке колоды, наличие карт для досдачи, сохранение общей суммы фишек, согласованность вкладов и ставок, очередь хода и завершение. Начинать игру следует через `start`: полная проверка произвольной импортированной последовательности событий относится к будущему воспроизведению.

Операции возвращают состояние только в точке решения или после окончательной выплаты. Вскрытие — автоматический переход; отдельный `HandState` со значением SHOWDOWN не публикуется. Даже `start` может сразу вернуть COMPLETE, если после коротких блайндов торговля невозможна.

## Допустимые действия

`LegalActions` содержит `canFold`, `canCheck`, `callAmount`, `Optional<BetRange> bet` и `Optional<BetRange> raise`. Вложенный `BetRange` задаёт включительные `minTo` и `maxTo`. Методы `canCall()`, `canBet()`, `canRaise()` и `types()` удобны для выбора действия. Для завершённой раздачи возвращается `LegalActions.none()`.

Все суммы бета и рейза означают полную ставку на текущей улице **после** действия:

- Стоимость колла — разница ставок, ограниченная оставшимся стеком. Ноль означает отсутствие колла.
- Максимум «до» — собственная ставка улицы плюс оставшийся стек.
- Минимальный бет — большой блайнд.
- Минимальный рейз — ставка соперника плюс последняя полная прибавка.
- Если минимум больше максимума, оба предела равны максимуму: доступен короткий олл-ин.
- После полного бета прибавкой становится его размер; после полного рейза — разница между новой ставкой и прежней ставкой соперника. Короткий олл-ин прибавку не уменьшает.
- Бет доступен, когда на улице ставок ещё нет. После лимпа большой блайнд может сделать чек или рейз, хотя доплата равна нулю.
- Фолд разрешён только против ставки. Против олл-ина доступны только фолд и колл; дальнейшие повышения исключены.

`apply` сначала проверяет аргументы, затем завершённость, очередь, доступность типа действия и границы суммы. Он создаёт новое состояние только после успешной проверки.

| Код `IllegalActionException` | Причина |
| --- | --- |
| `HAND_COMPLETE` | Выплата уже завершена |
| `NOT_YOUR_TURN` | Должен действовать другой игрок |
| `ACTION_UNAVAILABLE` | Этот тип действия сейчас недоступен |
| `BELOW_MINIMUM` | Сумма «до» меньше указанного минимума |
| `ABOVE_MAXIMUM` | Сумма «до» больше максимума |

Некорректные аргументы вызывающего кода, например место 2 или `null`, дают `IllegalArgumentException` либо `NullPointerException`. Отказ не меняет старое состояние и его историю.

## Закрытие торговли, возвраты и выплаты

При обычной торговле круг закрывается, когда оба игрока действовали и ставки равны. После лимпа ход большого блайнда сохраняется. На префлопе первым действует баттон, на остальных улицах — игрок без баттона. При переходе ставки улицы и отметки действий очищаются, минимум снова начинается с большого блайнда.

Если один игрок в олл-ине, а другой уже покрывает его ставку, доплаты больше нет: неуравненная часть возвращается, оставшиеся общие карты сдаются по улицам, затем обе руки оцениваются и банк выплачивается. Если второй игрок ещё должен доплатить, движок возвращает точку решения с фолдом и коллом. При фолде вскрытия и досдачи нет.

До выплаты выполняется равенство:

```text
stacks.total() + contributions.total() == startingStacks.total()
```

Возврат увеличивает стек и уменьшает вклад на одну сумму. После выплаты банк, вклады и ставки улицы равны нулю; сумма стеков равна исходной.

`HandResult` сохраняет данные завершённой раздачи:

| Значение | Смысл |
| --- | --- |
| `header()` | Идентификаторы и исходные параметры раздачи |
| `winnerSeat()`, `isTie()` | Победитель либо ничья; ничья возможна только на вскрытии |
| `contributions()` | Уравненные вклады **после возврата**, до выплаты |
| `returnedChips()` | Отдельные возвраты неуравненных фишек |
| `pot()` | Сумма уравненных вкладов до выплаты |
| `payouts()` | Выплаты из этого банка, без повторного включения возвратов |
| `finalStacks()` | Итоговые стеки |
| `wasShowdown()`, `ranks()` | Признак вскрытия и две лучшие пятёрки по местам; после фолда список пуст |

Для каждого места `finalStack = startingStack - contribution + payout`. При ничьей выплата равна уравненному вкладу. В текущей модели банк всегда чётный; правило будущей нечётной фишки закреплено за игроком без баттона.

Пример Т-7: олл-ин 10 000 против колла 4 000 даёт возврат 6 000, вклады `[4000, 4000]` и сыгранный банк 8 000. В итоговом `HandState` банк уже нулевой; исторические 8 000 доступны через `result.pot()`.

## История и представление игрока

Порядок фактов соответствует [контрактам событий](domain-model.md): блайнды баттона и соперника, агрегированные `deal_hole` мест 0 и 1, действия перед автоматическими событиями, положительный возврат перед досдачей и выплатами, борд по улицам, вскрытие и выплаты по возрастанию места. Нулевые денежные события не записываются. `Showdown.cards` — две закрытые карты; лучшая пятёрка хранится в `HandResult.ranks`.

`state.viewFor(seat)` возвращает только `PlayerView`: свои карты, борд, открытые суммы, метаданные, очередь и предназначенную игроку историю. Колоды и ссылки на `HandState` в этом типе нет. Допустимые действия доступны только в собственный ход, иначе возвращается пустой набор.

`HandHistory.forPlayer(seat)` всегда удаляет `DealHole` соперника, даже из завершённой истории. Публичные события `Showdown` сохраняются: `view.opponentCards()` возвращает карты только после такого события. При фолде карты соперника остаются скрытыми. Конструктор `PlayerView` выполняет проекцию истории и при прямом вызове; повторная проекция ничего не меняет.
